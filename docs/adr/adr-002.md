
1️⃣ What happens when a seller deletes a link?

You correctly noticed the issue:

links.destination_url

If the link is deleted (or edited), the purchase should still work.

The correct architecture is to snapshot delivery data at purchase time.

This is standard practice in ecommerce systems because orders must remain valid even if the original product changes or disappears.  ￼

⸻

Correct Solution

When purchase happens:

copy destination_url into purchases

Schema change:

purchases
--------
id
link_id
buyer_email
stripe_payment_id
amount
delivery_url
created_at

So purchase flow becomes:

buyer pays
↓
webhook confirmed
↓
create purchase
↓
delivery_url snapshot stored

Then unlock redirect uses:

purchase.delivery_url

NOT:

links.destination_url


⸻

Why this matters

Example scenario:

seller deletes product

But buyer purchased earlier.

Result:

purchase.delivery_url still exists

So unlock still works.

⸻

Updated rule

links.status = deleted

Behavior:

Action	Result
new buyers	cannot purchase
existing buyers	still unlock

2️⃣ Refund / Dispute UX

Stripe handles the financial side, but your platform still needs UX flows.

Define two flows.

⸻

Buyer Refund Flow

Buyer page:

/purchase/{id}

Button:

Request refund

Flow:

buyer submits request
↓
seller receives email
↓
seller approves or denies
↓
platform triggers Stripe refund

MVP simplification:

Refund request email goes to seller.

Seller decides.

⸻

Seller Dashboard Refund

Seller dashboard:

sales list
↓
purchase details
↓
refund button

Seller action:

refund purchase

System calls:

Stripe refund API

Then:

purchase.status = refunded


⸻

Purchase status enum

Add:

purchases.status

Values:

paid
refunded
disputed

⸻

/unlock-request

Flow:

enter email
↓
enter product URL or purchase id
↓
system finds purchase
↓

↓

This is extremely common in download systems.

⸻

6️⃣ Why Not Store Token in Purchases?

Because buyers may request multiple tokens.

Example:

token #1 expired
token #2 resent
token #3 resent

So tokens belong in a separate table.

⸻

7️⃣ Final Architecture Rule

Purchases must be immutable snapshots.

Meaning they store:

delivery_url
price_paid
product_title

This prevents future product edits from breaking past orders.

This pattern is standard in ecommerce systems because orders represent a historical snapshot of a transaction.  ￼
